# about

I have been self-taught since around 2013. It started where a lot of people start — tinkering with Minecraft and SA-MP servers — and that itch to change how things behaved never went away.

From there the path wound through PHP / backend, into Python, down to Linux and networking, then toward security — and lately building real things with the help of AI. I am a curious generalist: I would rather understand the layer beneath the abstraction than memorize the abstraction. I care about clean architecture, optimization, and the edge cases everyone else skips.

Above all I value simplicity. Like Apple's design philosophy, I believe the best design — and the best code — is the simple one: easy to read, easy to reason about, with nothing left to take away. Complexity is easy; clarity is the hard, worthwhile work.

# principles

A few principles I keep coming back to.

Simplicity first

The best code is the simple one — easy to read, easy to reason about, with nothing left to take away.

Stdlib-first, few dependencies

Reach for the standard library before adding a dependency — fewer moving parts, less to break.

Tested & verified

If it ships, it has tests — and I actually run them before calling it done.

Secure by default

Secrets in env, never in the repo; safe defaults; and a thought for the edge cases.

Understand under the hood

I'd rather understand the layer beneath the abstraction than memorize the abstraction.

Ship & iterate

Get it working and out the door, then make it better.
